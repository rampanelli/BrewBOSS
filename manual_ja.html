ユーザー操作マニュアル

BrewBOSS

WebインターフェースとLCD・キーパッドによるスタンドアロン操作を備えた醸造自動化コントローラーです。このガイドでは、システムを安全に操作する方法をステップバイステップで説明します。

BrewBOSSは、醸造日のマッシュ、ボイル、ポストボイルの各段階を自動化します。スマートフォンやPCのブラウザから操作することも、20×4 LCDと4つのボタンでスタンドアロン操作することも可能です — オンラインでもオフラインでも。

1. 概要

BrewBOSSは電動醸造機器用のコントローラーです。ヒーター、ポンプ、醸造日のタイマーを管理し、温度と進行状況をリアルタイムで報告します。

サポート: BeerSchoolフォーラムでBrewBOSS公式コミュニティに参加してください — セットアップを共有し、質問し、他のブルワーを助けましょう。

以下の3つの方法で操作でき、これらは連携して動作します：

  • Webインターフェース — デバイスが提供する単一ページ。ブラウザからすべてを制御できます。
  • LCDと4つのボタン — ネットワークがなくても完全なスタンドアロン操作が可能です。
  • REST API — オプション。統合やスクリプト用です。

できること：

  • プログラム可能なマッシュステップ、タイマー付きホップ添加による自動ボイル、温度トリガー添加と最終冷却を含むポストボイル段階を実行します。
  • 完全手動（直接出力）または事前プログラムされたレシピで操作します。
  • レシピの管理（作成、編集、保存、有効化、削除）とインポート — BeerSmith / Brewfatherなどのツールと互換性があり、独自のレシピをエクスポートおよびインポートできます。
  • ログの記録：詳細なマッシュグラフ用の温度CSV（1分ごとのサンプル、イベント付き）。特定の機器に合わせてレシピを微調整できます。
  • 停電後に自動復旧し、中断した場所から醸造を続行します。
  • 安全システム（過温度遮断およびセンサー喪失遮断）でバッチを保護します。
  • オンラインまたはオフラインで動作。20×4 LCDにステータスを表示します。
ハードウェア互換性ESP8266 (Wemos)、ESP32、ESP32-C3ボードで動作し、BrewManiacやBrewUNOなどの他のプロジェクトで使用されている配線と100%互換性があります — フラッシュするだけですぐに使用できます。

2. 前提条件とインストール

BrewBOSSを操作するには以下が必要です：

  • BrewBOSSファームウェアがインストールされた対応コントローラーボード（Wemos/ESP8266、ESP32、またはESP32-C3）。
  • 配線された醸造ハードウェア：SSR経由のヒーター、ポンプ、1つ以上のDS18B20温度センサー。オプションの20×4 I²C LCDと4つのボタンでスタンドアロン使用が可能です。
  • Webブラウザを搭載したスマートフォン、タブレット、またはコンピューター。
  • オプションで、自宅のWi‑Fiネットワーク（ない場合、デバイスは独自のアクセスポイントを作成します）。

ファームウェアのインストール（フラッシュ）

ボードがまだフラッシュされていない場合は、esptoolでファームウェアとファイルシステムを書き込みます：

  1. binariesフォルダからボード用の2つの.binファイルをダウンロードします：ファームウェア（_fsサフィックスなし — 最初にフラッシュ）とファイルシステム（_fsサフィックス — 2番目にフラッシュ）。
  2. 正しいオフセットにフラッシュします — 例えばWemos/ESP8266の場合（<version>をダウンロードしたバージョンに置き換えてください）：
esptool.py --chip esp8266 --port COMx write_flash 0x0 BrewBOSS_<version>_esp12e.bin
esptool.py --chip esp8266 --port COMx write_flash 0x200000 BrewBOSS_<version>_esp12e_fs.bin
完全なフラッシュガイドESP32 / ESP32-C3用のバイナリ、正確なオフセット、コマンドはプロジェクトのヘルプページにあります。ESP8266ファームウェアにはブートローダーが既に含まれているため、0x0に書き込みます。

3. システムへのアクセス

  1. コントローラーの電源を入れます。起動時にファイルシステム、Wi‑Fi、センサー、LCD、キーパッドが初期化されます。
  2. アクセスポイントに接続します。デフォルトでは、デバイスはBrewBOSSという名前のWi‑Fiネットワーク（パスワードbrewboss）を作成し、IPは192.168.4.1です。
  3. スマートフォン/PCでそのネットワークに接続し、ブラウザでhttp://192.168.4.1を開きます。
  4. ログインが有効な場合（設定 → システム → セキュリティ）、ログイン画面が表示されます。そうでない場合、インターフェースはフルアクセスで開きます。

ログインとアクセスレベル

アクセス保護はオプションで、デフォルトでは無効です（ログインなし）。有効にするには、設定 → システム → セキュリティに移動し、スイッチをオンにしてパスワードを設定し、保存します。有効な場合、デフォルトのパスワードはbrewbossです。

  • 正しいパスワードを入力 → ログイン：フルアクセス。セッションはデバイスが再起動するまで続きます。
  • 無視：読み取り専用アクセス — すべてを見ることはできますが、変更はできません。
  • 誤ったパスワード：再入力を求められ、最大10回の試行後、読み取り専用にフォールバックします。

設定 → システム → セキュリティでパスワードを変更または削除できます。空のパスワードはログインを完全に無効にします。

パスワードを忘れた場合ファイルシステムを再フラッシュするとbrewbossにリセットされます。

自宅のWi‑Fiに切り替える

コントローラーを自宅ネットワークに接続するには、設定 → システム → WiFiを開き、モードを選択してSSID/パスワードを入力し、保存して再起動します。

Wi‑FiモードAP = デバイスが独自のネットワーク（オフライン使用）。STATION = ルーターにのみ接続。MIXED = 両方を同時に。STATIONモードで60秒以内に接続できない場合、アクセスポイントにフォールバックします。

4. インターフェースのナビゲーション

インターフェースには左側にサイドメニュー、上部にステータスバーがあります。

サイドメニュー — 主な移動先：

  • ダッシュボード — ライブ温度、タイマー、コントロールボタンを備えたメイン画面。
  • レシピ — レシピライブラリとマッシュ/ボイルステップエディター。
  • 設定 — 調整、システム（ネットワーク、セキュリティ、時刻、バックアップ）、および情報。
  • モード — インターフェースのカラーテーマを切り替えます。
  • 情報 — バージョンとハードウェア情報。

ステータスバーをタップするとメニューが折りたたみ/展開されます（スマートフォンで便利です）。

ステータスバー — Wi‑Fiインジケーター、NTP（時計）ドット、HEAP（空きメモリ）ドット、デバイスの稼働時間。

5. ステップバイステップ操作

レシピを使った醸造日の典型的な流れは次のとおりです：

  1. 準備。ケトルに水を入れ、センサーを配置し、インターフェースに接続します。
  2. レシピを選択。レシピを開き、1つ選んで有効化します。
  3. 設定を確認。設定 → 調整で、温度単位、ボイル温度/時間、センサーを確認します。
  4. マッシュを開始。ダッシュボードでStartを押します。システムは最初のステップの目標温度まで加熱し、タイマーを実行します。
  5. 進行を追跡。ゲージとステップ履歴を確認します。ロックされたステップがビープ音を鳴らしたら、解除します。
  6. ボイル。最後のマッシュステップの後、システムは自動的にボイルに移行します。沸騰温度まで加熱し、タイマーを実行し、各ホップ添加を時間通りに発動します。
  7. ポストボイルと冷却。加熱をオフにして、冷却を監視し、温度ベースの添加をトリガーし、最終冷却ステップを実行します。
  8. 完了。ブザーが終了を知らせ、画面に総醸造時間が表示されます。
スケジュール開始（Delay）マッシュまたはボイルを後で開始するようにスケジュールできます。LCDにカウントダウンが表示され、ゼロになると自動的にプロセスが開始します。

6. 各画面の説明

以下の各セクションでは、画面名、表示内容、目的、操作方法を説明します。

6.1 — ダッシュボード（メイン）

表示内容。3つの円形ゲージとタイマーカードを備えたホーム画面：メイン温度、スパージ温度、出力（PWM）、現在のステップ名付き醸造タイマー。

目的。ここで醸造を開始、監視、停止し、ライブ状態を読み取ります。

操作方法。ゲージの下にあるコントロールボタンを使用します。手動モード中は、ゲージをタップして目標温度または出力を設定できます。

6.2 — ステップとステップ履歴

表示内容。現在のステップ/タイマーと、プロセスの各マイルストーンの実行リスト。

目的。醸造の正確な進行状況と直近の出来事を追跡します。

操作方法。読んで追跡します。イベントタイプは色分けされています。

6.3 — レシピ

表示内容。検索ボックスと並べ替え、インポートボタンを備えたレシピライブラリ。

目的。レシピを作成、保存、再利用します。

操作方法。レシピを有効化して醸造用に読み込みます。他の場所に保存したレシピをインポート。自分のレシピを保存/編集。不要になったレシピを削除します。

6.4 — マッシュステップエディター

表示内容。名前、目標温度、時間、ステップごとのフラグを含むマッシュステップのリスト。

目的。マッシュプロファイルを定義します。

操作方法。ステップを追加、編集、並べ替え。温度と時間を設定。フラグを設定：循環（ポンプ作動）、ヒーターオン、最大出力、ステップロック（手動操作のための一時停止）。

6.5 — ボイルと添加エディター

表示内容。ボイルプログラムと添加。

目的。ボイル中およびボイル後のホップ添加をスケジュールします。

操作方法。添加を追加し、各添加のトリガー方法を選択：タイマー添加（ボイル中）、ポストボイル添加（温度による）、最終冷却。

6.6 — 調整

表示内容。各バッチに適用される醸造パラメーター：単位、遅延、出力パーセント、ボイル温度/時間、スパージ、PIDバンド、ポンプタイミング、センサー割り当て、チェックボックス。

目的。コントローラーを機器に合わせます。

操作方法。値を設定し、保存を押します。センサーオフセットを使用して基準温度計に対して読み取り値を校正します。

6.7 — システム（ネットワーク、セキュリティ、時刻、バックアップ）

表示内容。デバイス設定パネル。

目的。ネットワーク、ログイン、時計、バックアップ。

操作方法。Wi‑Fiモードと認証情報、セキュリティ（ログインのオン/オフとパスワード）、NTPサーバーとGMTオフセット、バックアップ（設定のエクスポート/インポート）を設定します。

6.8 — 情報

表示内容。ファームウェアバージョン、ハードウェア、ネットワーク状態、時刻/NTP、システム情報。

目的。ヘルスチェックと、助けを求める際に含める情報。

操作方法。読み取り専用 — すべてが正常に動作していることを確認するために使用します。

6.9 — カラーテーマ（モード）

表示内容。異なるカラースキームのインターフェース。

目的。快適さと可読性 — 例えば、薄暗い醸造室用のダークテーマ。

操作方法。サイドメニューのモードをタップして、利用可能なカラースキームを切り替えます。

7. ボタン、フィールド、メッセージ、インジケーター

コントロールボタン（ダッシュボード）

  • Start — マッシュを開始します。
  • Pause / Resume — 一時停止と再開。
  • Stop — すべてを停止します。
  • Skip — 現在のマッシュステップをスキップします。
  • Boil — ボイルを直接開始します。
  • Pump — ポンプをオン/オフします。
  • Prime — 自動プライミングサイクルを実行します。

ステータスインジケーター

  • Wi‑Fi：ネットワーク接続時はdBm単位の信号強度、またはデバイスがアクセスポイントとして動作している場合はAP（緑）とアクセスポイント名。
  • NTPドット：時計が同期している場合は緑。
  • HEAPドット：空きメモリの状態。
  • 稼働時間：デバイスが動作している時間。

メッセージとイベント

ステップ履歴とLCDには、Brew STARTED、目標到達、ステップ完了、ホップ添加、完了などのイベントが表示されます。アラーム付きのSAFETYイベントは、保護機能が作動したことを意味します。

8. 操作モード

  • マッシュ — マッシュステップを実行。各ステップで目標まで加熱し、タイマーを実行し、次に進みます。最後のステップ後、自動的にボイルに移行します。
  • ボイル — ボイル温度まで加熱し、タイマーを実行し、タイマー添加を発動します。単独で開始することもできます。
  • ポストボイル — 加熱はオフ。冷却を監視し、温度ベースの添加をトリガーし、最終冷却ステップを実行します。
  • 手動 — ヒーター出力を直接設定します（オープンループ）。目標は参考値のみ。復旧用に保存されません。
  • Delay（スケジュール開始） — マッシュまたはボイルを遅延付きで開始。デバイスがカウントダウンし、自動的に開始します。

ポンプとプライミング

  • ポンプ — 手動でオン/オフ。循環ステップ中は自動制御されます。
  • プライミング — 開始前に配管を満たすための自動サイクル（5 × 3秒オン / 2秒オフ）。

9. スタンドアロン使用 — LCDと物理ボタン

Webインターフェースなしで醸造全体を実行できます。

20×4ディスプレイ

[w] BrewBOSS 00:14:32         <- Wi-Fiアイコン + タイトル + ステップタイマー
[H]  65.20>66   [W] 68% [P]   <- メイン: 現在>目標, 出力, PWM, ポンプ
[S]  74.00>74   100%        M <- スパージ: 現在>目標, PWM, フラグ B/M/L
Add Citra 30g@15'             <- 最後のイベントメッセージ (またはIP / AP)
  • 1行目 — Wi‑Fiアイコン + "BrewBOSS"、醸造中はステップタイマー。それ以外はバージョン。
  • 2行目 — メイン温度（現在>目標）、単位、ヒーター出力、PWM%、ポンプオンの場合はポンプアイコン。
  • 3行目 — スパージ温度とそのPWM%。フラグ：B（ボイル一時停止）、M（マッシュ一時停止）、L（ステップロック）。
  • 4行目 — 最後のイベントメッセージ。アイドル時はIP: <アドレス>またはAP: 192.168.4.1を表示。

醸造完了後、画面は15秒間お礼を表示し、その後いずれかのボタンを押すまで総醸造時間を表示します。

4つのボタン

4つのメンブレンキーパッドボタンには1–4の番号が付いています。各ボタンは3つの押下時間に反応します：短押し、長押し（約2秒）、超長押し（約3秒）。モード開始後の1.5秒のロックにより、誤停止を防止します。

押下1234
短押しポンプ オン/オフ出力 −10%出力 +10%一時停止 / 再開
長押し（約2秒）プライミング手動開始 / ステップスキップ / ロック解除ボイル開始マッシュ開始
超長押し（約3秒）—停止停止停止
  • ±10%の出力変更は、現在のモードのアクティブなヒーターに影響します。
  • マッシュ中、ボタン2の長押しで現在のステップをスキップします。ステップがロックされている場合、同じ長押しでロックを解除して進行します。
  • 完了後の「総時間」画面では、いずれかのボタンでホーム画面に戻ります。

10. 停電復旧

醸造中に停電が発生した場合、再起動時にデバイスは保存された状態を検出し、一時停止に入り、LCDに"復旧しました！再開しますか？"と表示します。

  1. ボタン4（短押し）を押して、中断した場所から再開します。
  2. 時計が同期されていた場合、残り時間はデバイスがオフだった時間に応じて調整されます。
注意手動モードは復旧されません（保存された状態がありません）。

11. 主な使用フロー（クイックリファレンス）

  1. 電源オン → BrewBOSSに接続 / 192.168.4.1を開く → ログイン。
  2. レシピ → レシピを有効化。
  3. 調整 → 単位、温度、センサーを確認。
  4. ダッシュボード → Prime（オプション） → Start。
  5. マッシュが実行され進行 → ボイルに移行 → 添加が時間通りに発動。
  6. ポストボイル / 冷却 → 完了（総時間が表示されます）。

12. ベストプラクティス

  • 最初の醸造前に、信頼できる温度計に対してセンサーオフセットを校正してください。
  • マッシュ開始前にプライミングを実行し、流量を確認してください。
  • デバイスを信頼できるWi‑Fiネットワークに接続してください — 接続はローカルネットワーク上でパスワードを平文で送信します。
  • 醸造をレシピとして保存し、温度ログ/CSVを使用して機器に合わせて微調整してください。
  • デバイスの設定完了後、バックアップ（エクスポート）を作成してください。
  • ヒーター周辺を整理してください。アクティブな醸造を完全に放置しないでください。

変更できない（読み取り専用）読み取り専用モードです。「読み取り専用 — タップしてログイン」バッジをタップし、パスワードを入力してください。
パスワードを忘れたファイルシステムを再フラッシュしてパスワードをbrewbossにリセットします。
ログの時刻が間違っている時計が同期されていません。システムでNTPサーバーとGMTオフセットを設定してください。
停電後に一時停止している復旧機能です。ボタン4（短押し）を押す（またはインターフェースを使用する）と再開します。

14. ファームウェアとインストール

3つの対応コントローラー用ファームウェア（LittleFSは別途提供）。ファイルシステムイメージはLittleFS形式です。

ファイルとオフセット

binariesフォルダの各リリースには、コントローラーごとに2つのファイルが含まれています：BrewBOSS_<version>_<board>.binはファームウェア（最初にフラッシュ）、BrewBOSS_<version>_<board>_fs.binはファイルシステム（LittleFS — 2番目にフラッシュ）。_fsで終わるファイルが常にファイルシステムで、サフィックスがない方がファームウェアです。<board>はesp12e（Wemos D1 Mini / ESP8266）、esp32（ESP32 WROOM-32）、またはesp32c3（ESP32-C3 Super Mini）です。

OTAファームウェアとファイルシステムの更新

BrewBOSSはWebインターフェースから直接Over-the-Air (OTA)更新をサポートしています。これにより、日常的な更新にUSBケーブルやesptoolが不要になります。最初にファームウェアファイル（_fsサフィックスなし）をアップロードし、次にファイルシステムファイル（_fsサフィックス）をアップロードします。

  • 仕組み：Webインターフェースで設定 → システム → ファームウェア更新にアクセスします。新しいファームウェアとファイルシステムのバイナリファイルをアップロードします。デバイスがフラッシュへの内部書き込みを処理し、再起動します。
  • 利点：
  • 安全性：ブートローダーに自動フォールバックが含まれており、更新が中断されてもデバイスが機能し続けることを保証します。
  • 効率性：手動でのオフセット計算なしで、ファームウェアバージョンとファイルシステム構造間のシームレスな移行。

前提条件

  • esptoolをインストール：pip install esptool
  • USBでコントローラーを接続し、シリアルポートを見つけます（例：WindowsではCOM5、Linuxでは/dev/ttyUSB0）。
  • .binファイルがあるフォルダからコマンドを実行します。
  • COMxを正しいポートに置き換えてください。高速フラッシュには--baud 460800を追加します。

フラッシュ（更新）

既に設定済みのコントローラーの場合、最初にファームウェア、次にファイルシステム（_fs）をフラッシュします — 2つの別々のステップ（より信頼性が高い）。<version>をダウンロードしたバージョンに置き換えてください：

Wemos / ESP8266 — ファームウェア

esptool.py --chip esp8266 --port COMx --baud 460800 write_flash 0x0 BrewBOSS_<version>_esp12e.bin

Wemos / ESP8266 — ファイルシステム

esptool.py --chip esp8266 --port COMx --baud 460800 write_flash 0x200000 BrewBOSS_<version>_esp12e_fs.bin

ESP32 (esp32dev) — ファームウェア

esptool.py --chip esp32 --port COMx --baud 460800 write_flash 0x10000 BrewBOSS_<version>_esp32.bin

ESP32 (esp32dev) — ファイルシステム

esptool.py --chip esp32 --port COMx --baud 460800 write_flash 0x290000 BrewBOSS_<version>_esp32_fs.bin

ESP32-C3 — ファームウェア

esptool.py --chip esp32c3 --port COMx --baud 460800 write_flash 0x10000 BrewBOSS_<version>_esp32c3.bin

ESP32-C3 — ファイルシステム

esptool.py --chip esp32c3 --port COMx --baud 460800 write_flash 0x290000 BrewBOSS_<version>_esp32c3_fs.bin
ESP8266 ファームウェアには既にブートローダー（eboot）が含まれているため、0x0に書き込みます。2つのファイルで十分です。

空のチップ / 初回フラッシュ（ESP32 / ESP32-C3）

erase_flash後または新品のチップでは、5つのファイルすべてを正しいオフセットにフラッシュする必要があります。ブートローダー、パーティションテーブル、boot_app0は既にbinariesフォルダに含まれています。

ESP32-C3 Super Mini - BOOTボタン初回フラッシュ（ブートローダーを0x0に）では、コマンド実行中にボード上のBOOTボタンを押し続ける必要があります。フラッシュ開始後に離してください。以降のフラッシュはボタンなしで実行されます。

1. ブートローダー

esptool.py --chip esp32c3 --port <port> --baud 460800 write_flash 0x0000 BrewBOSS_<version>_esp32c3_bootloader.bin

2. パーティションテーブル

esptool.py --chip esp32c3 --port <port> --baud 460800 write_flash 0x8000 BrewBOSS_<version>_esp32c3_partitions.bin

3. ブートアプリ

esptool.py --chip esp32c3 --port <port> --baud 460800 write_flash 0xe000 BrewBOSS_<version>_esp32c3_boot_app0.bin

4. ファームウェア

esptool.py --chip esp32c3 --port <port> --baud 460800 write_flash 0x10000 BrewBOSS_<version>_esp32c3.bin

5. ファイルシステム

esptool.py --chip esp32c3 --port <port> --baud 460800 write_flash 0x290000 BrewBOSS_<version>_esp32c3_fs.bin

ファームウェアのみの更新（ブートローダーはそのまま）

esptool.py --chip esp32c3 --port <port> --baud 460800 write_flash 0x10000 BrewBOSS_<version>_esp32c3.bin

ファイルシステムのみの更新

esptool.py --chip esp32c3 --port <port> --baud 460800 write_flash 0x290000 BrewBOSS_<version>_esp32c3_fs.bin
最初にすべて消去（オプション） esptool.py --chip <esp32|esp32c3|esp8266> --port COMx erase_flash。これによりLittleFSに保存されたWiFi/レシピ設定も消去されます。

注意事項

  • オフセットは現在のパーティションテーブル（4 MBフラッシュ）に対して有効です。テーブルが変更されると、オフセットも変わります。
  • イメージはLittleFS（SPIFFSではない）です — ファームウェアはファイルシステムをLittleFSとしてマウントします。
  • フラッシュ後、コントローラーはWebサーバーを起動します。ネットワークIPまたはAP経由でアクセスします。
  • ネイティブUSB搭載のESP32-C3：ポートはEspressifシリアルデバイス（VID 303A）として表示されます。フラッシュ用のリセット/ブートは自動です。
